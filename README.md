# Litops Atelier

Интернет-магазин браслетов ручной работы из натуральных камней. Витрина
экспортируется как статический Next.js-сайт для GitHub Pages, а общие данные
магазина хранятся в Neon.

## Возможности

- Next.js 16, React 19 и TypeScript;
- главная, каталог, универсальная карточка товара, корзина и избранное;
- закрытая панель управления с Neon Managed Auth;
- PostgreSQL и Neon Data API с Row Level Security;
- добавление и редактирование браслетов, цен, происхождения камней и остатков;
- Drag&Drop нескольких фотографий с автоматическим уменьшением до WebP;
- общие заказы, индивидуальные заявки и сообщения;
- редактируемые политика обработки данных, согласие, оферта и другие документы;
- импорт и экспорт резервной копии каталога;
- адаптивная вёрстка, Lenis-прокрутка и поддержка `prefers-reduced-motion`;
- автоматическая сборка и публикация через GitHub Actions;
- корректная работа по адресу GitHub Pages и на собственном домене.

## Архитектура backend

Клиент использует только публичные адреса Neon Auth и Data API. Строка прямого
подключения к PostgreSQL и пароль владельца никогда не попадают в сборку.

Схема находится в `neon/migrations/20260810_litops_cms.sql` и включает:

- `store_products` — карточки товаров;
- `product_images` — автоматически сжатые фотографии;
- `legal_documents` — документы сайта;
- `store_orders`, `custom_requests`, `contact_messages` — обращения клиентов;
- `admin_users` и одноразовые `admin_invites` — назначение владельца.

Опубликованные товары и документы доступны посетителям только для чтения.
Создание и изменение каталога, просмотр обращений и редактирование документов
разрешены только пользователям из `admin_users`. Первичная активация выполняется
одноразовым кодом, который хранится в базе только в виде SHA-256-хеша.

## Локальная проверка

Требуется Node.js 22 или новее.

```bash
cp .env.example .env.local
npm ci
npm run check
```

Готовый статический сайт создаётся в каталоге `out/`.

## Переменные сборки

```env
NEXT_PUBLIC_NEON_AUTH_URL=https://.../neondb/auth
NEXT_PUBLIC_NEON_DATA_API_URL=https://.../neondb/rest/v1
```

Оба значения являются публичными адресами. Доступ к данным защищают короткоживущие
JWT, права PostgreSQL и RLS-политики, а не скрытый ключ в браузере.

Workflow `.github/workflows/deploy-pages.yml` уже содержит адреса рабочего
проекта Litops Atelier. При переносе backend их можно переопределить переменными
репозитория с теми же именами.

## Первая активация владельца

1. Откройте `/admin/` и выберите «Первая активация владельца».
2. Укажите email, новый пароль длиной не менее восьми символов и одноразовый код.
3. После успешной активации код становится недействительным.
4. Последующие входы выполняются обычным email и паролем.

Перед использованием собственного домена добавьте точные origins без завершающего
слеша в Neon Console → Auth → Configuration → Domains:

- `https://dasuk03.github.io`;
- `https://litopsatelier.ru`;
- `https://www.litopsatelier.ru` — только если будет использоваться версия с `www`.

Перед коммерческим запуском заполните реальные сведения о продавце, ИНН,
контакты и адрес для обращений. Встроенные тексты документов являются
структурированными заготовками и должны быть проверены под фактический статус
продавца, способы оплаты, доставки и применимые требования к обработке данных.
