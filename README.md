# Litops Atelier

Production-версия интернет-магазина браслетов ручной работы из натуральных
камней. Сайт подготовлен для GitHub Pages и домена `litopsatelier.ru`.

## Возможности

- Next.js 16, React 19 и TypeScript;
- полностью статический экспорт без зависимости от ChatGPT Sites;
- главная, каталог, универсальная карточка товара, корзина и избранное;
- защищённая панель управления с общей базой товаров и заявок;
- добавление и редактирование браслетов, цен, происхождения камней и фотографий;
- загрузка фотографий Drag&Drop в объектное хранилище;
- редактируемые политика обработки данных, согласие, оферта и другие документы;
- адаптивная вёрстка, Lenis-прокрутка и поддержка `prefers-reduced-motion`;
- локальные изображения без Google Fonts и внешних медиахостингов;
- sitemap, robots.txt, Open Graph и SEO-метаданные;
- автоматическая сборка и публикация через GitHub Actions;
- корректная работа как по техническому адресу Pages, так и на собственном домене.

## Локальная проверка

Требуется Node.js 22 или новее.

```bash
npm ci
npm run check
```

Готовый статический сайт создаётся в каталоге `out/`.

## Публикация

Workflow `.github/workflows/deploy-pages.yml` собирает и публикует сайт после
каждого обновления ветки `main`. В `Settings → Pages` источником публикации
должен быть выбран `GitHub Actions`.

После первого успешного запуска в `Settings → Pages → Custom domain` укажите
`litopsatelier.ru`, сохраните и затем замените DNS-записи у REG.RU на адреса
GitHub Pages. После проверки домена включите `Enforce HTTPS`.

## Подключение панели управления

Панель использует Supabase Auth, Postgres, Row Level Security и Storage. Пароль
администратора не хранится в репозитории или статической сборке.

Для реальных заказов граждан РФ backend следует разместить в российском
дата-центре (например, self-hosted Supabase на российском VPS). Облачный
Supabase можно использовать для разработки и каталога без персональных данных,
но у него нет региона хранения данных в России. Переменные окружения одинаково
работают с облачным и self-hosted вариантом.

1. Создайте проект Supabase.
2. Выполните SQL из
   `supabase/migrations/20260810_litops_cms.sql` в SQL Editor.
3. В `Authentication → Users` создайте пользователя с email и паролем.
4. Выполните в SQL Editor, подставив email созданного пользователя:

```sql
insert into public.admin_users (user_id)
select id from auth.users where email = 'owner@example.com';
```

5. В GitHub откройте `Settings → Secrets and variables → Actions → Variables`
   и создайте:

   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL;
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — publishable/anon key.

6. Запустите workflow Pages повторно. После публикации откройте `/admin/`,
   войдите и нажмите «Опубликовать каталог», если общая таблица товаров пуста.

Перед коммерческим запуском заполните в редакторе документов реальные сведения
о продавце, ИНН, контакты и адрес для обращений. Встроенные тексты являются
структурированными заготовками и должны быть проверены под фактический статус
продавца и используемые способы оплаты/доставки.
